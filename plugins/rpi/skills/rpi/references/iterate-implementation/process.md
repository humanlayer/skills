# Iterate Implementation

Apply bug reports, review feedback, or follow-on changes to code already underway.

Follow these steps in order.

## 1. Read the Feedback and Workflow Context

Read the available outline, design, and research documents and the user's named sources in full. Read `$SKILLBASE/references/implement-outline/process.md` for document precedence. Read supporting resources as needed.

## 2. Understand the Implemented Work

Inspect the current diff and relevant commits. Compare the agreed behavior with the current code and tests. For an unstarted outline phase, read `$SKILLBASE/references/implement-outline/process.md` and use its normal implementation process.

## 3. Verify the Reported Behavior

Reproduce the issue or check the requested change against code and tests. Use relevant logs or fixtures when needed. If the expected behavior is unclear, ask one targeted question with a recommended approach.

## 4. Apply and Verify the Change

Implement the confirmed fix following existing patterns. Add a regression test where appropriate and run the relevant checks. Update affected design or outline sections when the agreed result changes. Keep outline validation markers accurate.

## 5. Read the Final-Answer Template and Respond

Read `$SKILLBASE/references/iterate-implementation/references/iterate_implementation_final_answer.md` and report the change, evidence, and remaining review steps.

When a workflow document was updated, offer to open it for review in VS Code, Cursor, or the user's preferred editor or browser.
